# Accounts and account types

An **account** is a tenant: the unit that owns users (through [membership](account-roles-and-membership.md)), [invitations](account-invitations.md), and optionally its own host and Postgres schema. Older code and commits call it a *customer*; it was renamed in 7c1dcac.[^commit-rename]

## Schema

The backend `Account` type exposes these fields in camelCase. Create input may also carry a transient `useSeparateDatabase` flag.[^account-type]

| Field | Meaning | Rules |
| --- | --- | --- |
| `id` | UUID, generated by the database | primary key[^queries] |
| `name` | Display name | required, 1–255 characters[^schema] |
| `individual` | `true` for a person, `false` for an organization | required boolean, default `FALSE` in the database[^queries][^schema] |
| `registeredNumber`, `taxId` | Company registration and tax ids | optional, ≤255; the frontends null them for individuals[^schema] |
| `slug` | Tenant subdomain: `<slug>.<rootDomain>` | unique; `VARCHAR(24)`; see slug rules[^queries] |
| `domain` | Custom host for the tenant | lowercase FQDN, ≤255, checked for collisions with other accounts at creation[^schema][^service] |
| `database` | Name of the tenant's own Postgres schema, if any | unique; generated, never chosen by the user in the product flow ([tenant schema isolation](../architecture/tenant-schema-isolation.md))[^queries] |
| `typeId` | Optional [account type](#account-types) | FK, `ON DELETE SET NULL`[^queries] |

## Business rules enforced in code

### Slug

- The pattern is `^(?!.*-+$)[\da-z][\da-z-]{0,23}([\da-z])?$`: lowercase letters, digits, and hyphens, starting alphanumeric and not ending with a hyphen.[^schema] Tests accept `a`, `1tenant`, `a-1` and reject `A`, `-ab`, `a1-`, `a b`, and the empty string.[^slug-test]
- **Required** when `subdomains` is `"required"`, optional otherwise.[^schema]
- Dropped entirely, along with `domain`, when `subdomains` is `"disabled"`, on both create and update.[^service] 7b51d48 removed slug and domain from the edit input.[^commit-update-input] The GraphQL update input only exposes `registeredNumber` and `taxId`.[^graphql]
- **Unique:** a clash raises `ERROR_SLUG_ALREADY_EXISTS`; a clash on the domain raises `ERROR_DOMAIN_ALREADY_EXISTS`. Both are 422.[^service]
- **Reserved:** a reserved slug raises `ERROR_INVALID_SLUG` (422).[^validate]

### Reserved slugs: what the code actually does

`getInvalidSlugs` starts from `saasConfig.invalid.slugs`, then pushes the main app's subdomain and every `apps[].subdomain` onto that array.[^invalid-slugs] The default list therefore reserves `admin` plus `app` (or the configured main-app subdomain).

`getSaasConfig` builds that list as `saasConfig.invalid?.domains || ["admin"]`, reading **`invalid.domains`, not `invalid.slugs`**.[^config] The line dates to 0d56cd3.[^commit-invalid]

*Inference from the code:*

- A configured `saas.invalid.slugs` is ignored.
- Configuring `saas.invalid.domains` replaces the `["admin"]` slug default with the list of domains.
- In that case `getInvalidSlugs` pushes subdomains onto the *same array object* held in the application's config on every validation. The reserved-domain list then also contains `app`, `admin`, and so on, and grows with each call.

### Domain

- The pattern is `^([\da-z]([\da-z-]{0,61}[\da-z])?\.)+[a-z]{2,}$`: lowercase labels of up to 63 characters, with a TLD of at least two letters.[^schema] Tests reject uppercase, a bare label, a leading dot, and a 64-character label.[^domain-test]
- A domain on the reserved-domains list raises `ERROR_INVALID_DOMAIN`.[^validate]
- *Inference:* collision checks only run when a slug is present, because `preCreate` calls `validateSlugOrDomain` inside `if (data.slug)`. A domain without a slug is already dropped before that point.[^service]

### Individual vs organization

The frontends' `entity` setting (`"individual"`, `"organization"`, or `"both"`) decides which fields the account form shows, and whether `individual` is fixed or chosen. With `"both"` the user chooses.[^react-fields] The backend only requires `individual` to be a boolean.[^schema]

## Account types

An **account type** is a classification an account can point at. It declares whether it applies to individuals, organizations, or both (`for_individual`, `for_organization`), and has a localized name per two-letter locale in `account_types_i18n`.[^queries]

- Create and update run in one transaction. Update **replaces all** i18n rows: it deletes them, then re-inserts.[^account-types-service]
- Deleting a type cascades to its i18n rows and sets `accounts.type_id` to `NULL`.[^queries]
- Read routes are public; write routes require a session. See [saas-fastify](../components/saas-fastify.md#http-surface).

## Account addresses

An `account_addresses` table (type, street, city, zip, state, 2-letter country) is created and cascades on account deletion.[^queries] No service, route, or frontend in this repository reads or writes it.

## Open questions

- Is `invalid.slugs` reading `invalid.domains` a bug? The resulting mutation of the configured array looks unintended.
- What is `account_addresses.type_id` meant to reference, and is address management planned or left to host apps?
- What does an account *type* mean to the business beyond individual/organization applicability?
